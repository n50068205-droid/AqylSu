# 🎓 Шпаргалка для защиты проекта AqylSu

Всё, что нужно для уверенного выступления перед жюри: план на 3–5 минут, сценарий показа и ответы на частые вопросы.

> Перед выступлением откройте `index.html` и проверьте, что всё работает. Лучше иметь запасной вариант: файл на флешке и ссылку на GitHub Pages.

---

## ⏱ План выступления (3–5 минут)

### 1. Проблема (30 секунд)
> «Полив “на глаз” тратит лишнюю воду: растения то пересыхают, то заливаются. Фермеру трудно следить за каждой грядкой вручную».

### 2. Идея (30 секунд)
> «AqylSu следит за влажностью почвы каждой грядки, сама определяет, где нужен полив, считает время и литры и останавливается, когда цель достигнута».

### 3. Живая демонстрация (2 минуты)

1. Откройте **«Главную»**. Покажите карточку «Нужен полив» и предупреждение по участку.
2. Перейдите в **«Камеру 3D»**. Выберите грядку **А1**: видна влажность, порог и цель.
3. Нажмите **«Полить грядку»**. Вода появляется только на выбранной грядке, влажность растёт.
4. Включите скорость **15 мин/с**, чтобы показать результат быстро.
5. Откройте **«План полива»**. Покажите список «Что полить сейчас» с минутами и литрами.
6. Откройте **«Историю»** и скачайте **CSV**. Покажите **резервную копию** в «Настройках».

### 4. Итоги и развитие (1 минута)
> «Сейчас это учебная модель, но архитектура готова к подключению реальных датчиков на ESP32 или Arduino. Дальше планируем погоду, уведомления в Telegram и казахский язык».

## ❓ Вероятные вопросы жюри

**Это работает с реальными датчиками?**
Пока нет. Показания моделируются, это учебная симуляция. Логика принятия решений (порог, цель, лимит времени, остановка при пустом баке) устроена так, как работала бы с реальными данными. Следующий шаг — подключение датчиков и реле.

**Чем это лучше обычного таймера полива?**
Таймер поливает по расписанию независимо от почвы. AqylSu поливает по фактической влажности, считает расход воды и не тратит её там, где влажность в норме.

**Как рассчитываются время и расход воды?**
По упрощённой модели: от текущей влажности до целевой с учётом расхода линии и площади участка. Это не норма полива для реального поля, а демонстрационный расчёт.

**Что будет, если вода в резервуаре закончится?**
Насосы останавливаются, система показывает предупреждение «В резервуаре закончилась вода», полив ставится на паузу.

**Где хранятся данные? Они в безопасности?**
Только в браузере пользователя (`localStorage`). Ничего не отправляется на сервер. Есть резервная копия в JSON и экспорт в CSV.

**Почему один HTML-файл, без фреймворков?**
Чтобы проект открывался где угодно: без установки, без интернета, без сервера. Это удобно для демонстрации и для школ и хозяйств с плохой связью.

**Кто может этим пользоваться?**
Фермеры и садоводы для понимания принципа, учителя и студенты для обучения, разработчики как основа для реального контроллера.

**Какие культуры поддерживаются?**
Помидоры, огурцы, перец, есть демопрофили со значениями по умолчанию. Пороги и цели можно настроить вручную для каждого участка.

**Что вы сделали сами?**
Весь интерфейс, 3D-сцену, логику автополива, планировщик, историю, экспорт и импорт данных. Проект написан без сторонних библиотек.

## 🧰 Если что-то пошло не так

| Проблема | Решение |
|---|---|
| Данных нет или всё пусто | «Настройки» → «Восстановить из файла», загрузите JSON-копию |
| Интернета нет | Не страшно: приложение работает офлайн, откройте `index.html` |
| Нужно быстро показать результат | Скорость **15 мин/с** и кнопка **«+1 мин»** на паузе |
| Хочется начать с чистого листа | Очистите данные сайта в браузере и обновите страницу |
